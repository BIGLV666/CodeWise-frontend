# CodeWise 前端阶段总结与维护说明

## 1. 本阶段完成内容

### 主页与个人信息

- 调整主页为更舒展的 LeetCode 风格浅色布局。
- 接入用户头像、个人信息和题目记录相关接口。
- 题目列表使用游标分页，避免一次加载大量记录。
- 题目状态统一为：`0` 未尝试、`1` 已通过、`2` 尝试过但未通过。

### 收藏夹

- 收藏夹列表、题目列表和进度信息改为后端真实数据。
- 支持创建、修改、删除收藏夹，以及添加和移出收藏题目。
- 从收藏夹进入题目详情时保留来源，返回操作会回到收藏夹。
- 用户 ID 按字符串处理，避免雪花 ID 超出 JavaScript 安全整数范围。

### 复习

- 首页入口调整为“去复习”。
- 复习页接入当日复习记录和题目数据。
- 从复习进入题目详情后，提交代码携带 `submitScene: "REVIEW"`。
- SM-2 配置提供轻松、标准、紧张三种预设，高级参数折叠显示。

### 讨论区

- 新增讨论首页、帖子详情和帖子编辑页面。
- 支持帖子游标分页、热门帖子、标题搜索、标签筛选和题目搜索。
- 支持发帖、修改帖子、删除帖子、评论、回复、点赞和删除评论。
- 帖子和评论操作按钮根据当前用户 ID 控制显示，后端继续负责最终权限校验。
- 修改帖子复用发布编辑器，通过 `postId` 加载并回填原始内容。

## 2. Markdown 渲染

讨论区统一通过 `src/utils/markdown.ts` 渲染 Markdown，编辑预览和帖子详情共用同一套配置。

当前支持：

- GFM 标题、列表、引用、表格、删除线和任务列表。
- KaTeX 行内公式 `$x = 1$` 和块级公式 `$$...$$`。
- Java、JavaScript、TypeScript、Python、C++、SQL、HTML、CSS、JSON、Shell 代码高亮。
- 外部链接安全打开、图片懒加载和 DOMPurify 内容过滤。

Markdown 编辑器使用固定高度工作区，正文输入区和右侧预览区分别滚动。这样粘贴长文本时不会撑高整个页面，也不会把标题、标签和发布按钮推离当前视口。移动端会恢复为上下排列，保证可读性。

Spring 配置中的 `${ENV_NAME}` 不会被当作公式。公式分隔符必须成对出现，不要在一个 `$...$` 公式内部嵌套新的 `$`。

代码高亮基于 Highlight.js 精简核心，已显式注册 `plaintext` 作为未知语言的回退。Markdown 渲染函数带异常兜底，单个错误公式或代码块不应破坏整个发布页面。

完整测试内容位于项目根目录 `markdown-render-test.md`。

## 3. API 约定

- 普通 HTTP 请求统一通过共享 `request` 封装和网关 `/api` 访问。
- 前端不直接访问具体微服务端口。
- WebSocket 暂时保留现有连接方式，本阶段未调整。
- `userId` 始终转换为字符串后保存和比较。
- 其他 ID 当前可使用数字；需要与雪花 ID 比较时再转换为字符串。
- 后端 `Result<String>` 的业务字符串可能位于 `message`，一次性 `requestId` 按该规则读取。
- 列表接口优先使用游标分页，通过 `nextCursor` 和 `hasNext` 继续加载，不强依赖精确 `total`。

## 5. 后续维护建议

1. 新增接口时先在对应 `src/api/*Api.ts` 中封装，页面不要直接拼接服务地址。
2. 页面只负责数据加载和区域协作，组件按完整功能区域拆分，不要拆成过多小组件。
3. 帖子渲染能力统一修改 `src/utils/markdown.ts`，不要在页面内单独调用 `marked.parse()`。
4. 新增代码高亮语言时按需注册，避免引入 Highlight.js 全语言包。
5. 新增用户归属判断时统一使用字符串 ID；前端隐藏按钮不能替代后端权限校验。
6. 大列表继续使用游标分页，详情数据在用户进入详情页时再加载。
7. 修改完成后至少运行 `pnpm type-check`；路由、依赖或构建配置变更还应运行 `pnpm build`。
